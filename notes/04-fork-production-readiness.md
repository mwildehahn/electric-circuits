# Fork production-readiness audit

**Scope:** static audit of this fork as checked out on 2026-08-22. I read the requested system,
deployment, internal-engine, live-query, and package documentation and inspected the relevant Rust,
TypeScript, Docker, CI, and test code. No long-running suite was executed for this note; findings are
therefore code/documentation evidence, not a claim of runtime reproduction.

## Verdict

The data-correctness core is unusually well specified and defended. It has credible fencing,
at-least-once-to-exactly-once-effect recovery, explicit epoch/drift retirement, and meaningful
conformance coverage. It is **not yet safe to present as a general multi-tenant or Internet-facing
production service**. The principal blockers are an unauthenticated, destructive control/data plane,
unsafe-by-default Compose durability, and unbounded work queues / creation buffers. It is best suited
today to a single trusted network boundary with a persistent durable-streams deployment and controlled
workload admission.

## Prioritized gaps

| Priority | Gap and impact | Evidence | Recommended production gate |
|---|---|---|---|
| **P0** | **No authentication or authorization boundary for the native API/control plane.** `ELECTRIC_SECRET` protects only `GET /v1/shape`; every native control route is installed without middleware. A reachable caller can create arbitrary shapes/query-back data, enumerate topology/state and rows, reset metrics, delete rows from Postgres, force-purge a shape, or reset a broken epoch (which destroys every shape stream). The tRPC API likewise creates a context with only `core`, so it exposes schema definition, library-mode writes, shape lifecycle, and queries without caller identity. This is direct data exfiltration and modification, not merely a debug-information issue. | `apps/engine/src/http.rs:23-69` installs all routes without auth; destructive handlers at `:570-581`, `:644-680`, `:767-781`; only `apps/engine/src/electric.rs:834-835` checks the secret. `apps/api/src/server.ts:16-31` and `router.ts` have no auth context or authorization. `docs/deployment-postgres.md` explicitly says introspection is unauthenticated. | Require an authenticated principal plus table/row/operation authorization at the engine and API boundary; split or disable admin/debug/write routes in normal serving; make protected-by-default deployment manifests. Treat a single shared secret as compatibility-only, not tenant authorization. |
| **P0** | **The direct durable-streams data plane is exposed and unprotected in the supplied stack.** The client deliberately reads `streamUrl` directly, bypassing the API; the Compose file publishes durable-streams on the host. Shape streams carry result rows and the same service stores `changes/*` and `meta/catalog`. No credential/capability is passed in the returned handle. Even perfect API authentication would not protect direct stream URLs without an authenticated stream service or a broker/proxy. | `packages/client` and `apps/api/README.md` document direct stream reads; `apps/api/src/core.ts` returns `streamUrl`; `docker/compose.yaml:37-50` publishes port 8791; `docker/Dockerfile.ds` starts the server with no auth configuration. | Do not publish DS publicly; give each client signed, scoped, expiring read capabilities or proxy reads through an authorization layer. Separate internal change/catalog streams from client-readable shape streams. Add an integration test proving cross-tenant reads/writes and admin calls are rejected. |
| **P1** | **The default Docker stack intentionally uses memory-only streams.** `pnpm docker:up` is the documented whole stack, but `DS_MEMORY` defaults to `1`; a restart loses the catalog, shape streams, and change log. Postgres replication may already have advanced, so those lost client-facing records cannot be reconstructed automatically from the acknowledged slot. This is fine for demo/benchmark use but is a dangerous deploy default. | `docker/compose.yaml:41-50`, especially `DS_MEMORY: "${DS_MEMORY-1}"`; Docker README describes the stack as containerized; the architecture relies on durable `meta/catalog`, `changes/<n>`, and `shape/<id>` streams for recovery. | Publish separate `compose.dev.yaml` and production manifests. Production must require durable DS storage, backup/restore procedures, disk/IOPS sizing, and startup checks that reject memory durability outside an explicit development mode. |
| **P1** | **Backpressure is incomplete: several lossless paths are intentionally unbounded.** Subquery flip work and each ordered emission lane use Tokio unbounded channels; if DS slows, queues can grow without a byte/count ceiling. A pending shape buffers every replicated envelope during its backfill, and creation begins before the backfill completes; concurrent slow/backlogged creates multiply this memory. The sequencer also accumulates an entire source transaction's `txn_pending` fan-out. The ingestor spill cap does not bound any of these later stages. Result: a slow storage dependency, large transaction, or shape-creation flood can OOM the process before retention helps. | `apps/engine/src/engine/emission.rs:35-85`; `engine/mod.rs:296-322` uses an unbounded flip queue; `engine/sequencer.rs:289-295, 722-727, 689-756`; `engine/lifecycle.rs:457-480`; docs explicitly scope the transaction bound to the ingestor (`docs/deployment-postgres.md`, “Large transactions”). | Add byte-accounted bounded queues and admission/rejection/timeout policy for flip work, pending creates, pending fan-out, and per-request snapshots. Propagate bounded backpressure to the sequencer/ingestor before memory exhaustion; export queue depth/bytes, wait time, shed/reject counts, and alerts. Add overload/slow-DS tests. |
| **P1** | **Large and high-cardinality snapshots have unbounded materialization points.** A subquery node seed uses `collect()` into a `Vec<Row>`; outer subquery creation also retains a full `HashSet` of seeded PKs. The Electric adapter folds a whole shape stream into a map/vector, then constructs all response messages and keys before replying. An authorized (currently unauthenticated) broad query or a large inner set can therefore cause a one-request memory spike. | `apps/engine/src/engine/lifecycle.rs:1690-1694, 1705-1720`; `apps/engine/src/electric.rs:526-531, 908-925`; `docs/ARCHITECTURE.md` §4 acknowledges the adapter holds a whole snapshot. | Define max result rows/bytes and an admission budget; stream or paginate snapshot responses where protocol permits, and isolate/limit Electric snapshots. For inner-set seeding, batch directly into spill-backed state or reject/route oversized nodes with a clear quota. |
| **P1** | **Availability/scaling remains single-active rather than HA.** One sequencer and one active walsender own the state; the Kubernetes guidance deliberately specifies one replica. A second pod waits on a busy slot and is neither an active peer nor a hot standby. Separate slots create independent engines, not replicated service state. This is a valid first deployment mode, but it needs an explicit availability SLO, failover/runbook, and a chosen leader/fencing design before a production HA claim. | `docs/deployment-postgres.md` Kubernetes section (“ONE replica”); `docs/ARCHITECTURE.md` §5.1 and §10 (“ONE … sequencer”); `AGENTS.md` states a single LSN-ordered sequencer. | Document supported topology as single-writer explicitly in the product contract. For HA, implement lease/leader election plus fencing and tested promotion, or ship a supported active/passive controller with RTO/RPO and rolling-upgrade drills. |
| **P1** | **Prometheus compatibility contract is documented but unimplemented.** Fleet documentation promises `GET /metrics` on `ELECTRIC_PROMETHEUS_PORT`; the binary merely logs that the listener is not implemented and leaves `/metrics/prometheus` on the main listener. Operators using the documented port will lose monitoring rather than fail startup. | `docs/fleet-conformance.md` §§3 and 5; `apps/engine/src/main.rs:65-69`; config still accepts `ELECTRIC_PROMETHEUS_PORT` in `config.rs`. | Either implement the dedicated authenticated listener and contract-test it, or reject the setting at boot and correct every doc. Make metrics scraping/auth/TLS part of the standard deployment chart. |
| **P1** | **Compatibility/release gates are incomplete.** CI runs Rust tests, typecheck, and `pnpm test`, but not Electric’s separate oracle/property suite. The latter documents 13/15 subquery integration tests passing and two intentionally unsupported tag assertions. Package version is `0.0.0`/private and catalog format cutovers are boot-fatal, directing operators to reset durable-streams data; there is no documented versioned catalog migration/rollback policy. | `.github/workflows/ci.yml`; `electric-conformance/README.md` “13 / 15 pass”; root `package.json:4`; `apps/engine/src/engine/catalog.rs:460-545` rejects prior catalog formats and instructs reset. | Gate releases on the external conformance suite (or publish a reproducible pinned CI image), track the two deviations as an explicit supported-compatibility matrix, semver the wire/client/catalog contracts, and provide tested catalog/stream migration plus rollback/runbook. |
| **P1** | **There is no current capacity or benchmark evidence for the new execution/memory model.** Multiple core documents label memory/benchmark claims “fresh benchmarks pending.” Tooling exists, but no checked-in, versioned, reproducible results or SLO thresholds establish safe shape count, mutation rate, DS latency, backfill, failure, or recovery capacity. | `docs/ivm-engine-internals.md:42` and benchmark sections; `packages/bench/README.md` explicitly says fresh benchmarks pending; `docs/memory-model.md` has the same caveat. | Publish Linux CI/nightly benchmark reports with source revision, configuration, dataset and DS durability. | **P1** | **TLS and container hardening are not production-ready by default.** The deployment guide demonstrates an `https://` DS URL, but the engine compiles `reqwest` with TLS disabled and its own Docker comment says it supports plain HTTP only. ## Already strong

These areas are production-grade foundations, subject to the deployment limitations above:

- **Backfill/live correctness:** `pg::SnapshotGate` uses xid visibility rather than a tempting but
  unsound LSN-only fence; creation is two-phase so changes are buffered before the snapshot.
  (`apps/engine/src/pg.rs`, `engine/sequencer.rs`, `docs/ARCHITECTURE.md` §§3–5.)
- **Recovery and durability semantics:** commit-end markers, `(lsn, seq)` high-water checkpointing,
  append-before-slot-ack, segmented change logs, durable-before-client-ack catalog events, and
  `Dropped`/`Retired` retirement intent/completion are carefully designed and extensively explained.
  (`replication.rs`, `engine/catalog.rs`, `changelog.rs`, `engine/retirement.rs`, ADRs 0003/0006/0007/0008.)
- **Replication lifecycle safety:** slot identity is bound to a catalog epoch and slot loss is
  fail-closed or explicitly resets shapes; it is not silently recreated at WAL head.
  (`engine/epoch.rs`, ADR 0004.)
- **Schema safety:** relation fingerprints, a reconciler, `TRUNCATE` retirement, per-table schema
  generations/resolve locks, and unresolved-table refusal favor resync over stale serving.
  (`engine/drift.rs`, `pg.rs`, ADR 0005.)
- **Retention and disk hygiene:** active/dormant/evicted semantics, lease claims, stream close before
  deletion, segment pins, and durable retirement retries address common leaked-stream failure modes.
  (`retention.rs`, `engine/lifecycle.rs`, `changelog.rs`.)
- **Observability and graceful operations:** readiness is correctly distinct from liveness; the
  shutdown path drains and checkpoints; metrics cover WAL retention/flush lag, spills, held runs,
  catalog retry, retention, and memory cardinalities. (`main.rs`, `shutdown.rs`, `metrics.rs`,
  `mem.rs`, engine README.)
- **Correctness testing is broad:** native conformance exercises live Postgres replication, fuzzing,
  NULLs, concurrency, drift, retention, large transactions, shutdown and retirement completion;
  the separate Electric oracle harness gives useful protocol evidence. The missing CI/release gate is
  a delivery problem, not absence of test assets. (`packages/conformance`, `electric-conformance`.)

## Practical launch bar

Before serving untrusted clients: close both P0 items, make durable DS/TLS/non-root/network isolation
the default deployment, bound every queue/snapshot/creation path, and publish an authenticated
production manifest. Before claiming HA or broad scale: add a supported topology/failover contract,
release-gate external conformance, and publish reproducible benchmark and recovery evidence.
