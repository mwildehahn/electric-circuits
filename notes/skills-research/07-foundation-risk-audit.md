# Foundation risk audit before parallel implementation

Status: pre-implementation audit, 2026-08-23. This is a risk memo, not a task registry or a replacement for the canonical plan.

Reviewed: [AGENTS.md](../../AGENTS.md), canonical [note 18](../18-production-readiness-spec-reviewed.md), the Swift E2E map ([note 23](../23-swift-app-e2e-tdd-map.md)), the PG18/E2E addendum ([note 24](../24-postgres18-and-e2e-tdd-addendum.md)), and the differential-review disposition ([note 25](../25-pg18-e2e-differential-review-disposition.md)).

## P0 — Do not describe target state as current capability

**Risk.** The notes specify a target profile, while the repository still exposes direct engine/Electric and control surfaces and development Compose is pinned to PG16. Canonical readiness is explicitly no-go: the gateway/tenant boundary, production DS/restore qualification, PG18 topology, virtual-generated-column admission, slot/TLS proof, and real app qualification remain open. Treating the target as present invites unsafe deployment edits and false green claims.

**Foundation wording.** “Everything below is target-state work, not a statement of current production support. Current behavior is an inherited control only when the named scenario proves it. No release, public exposure, or production readiness claim is authorized until the selected profile's generated closure passes.”

**Route.** Opening status block: pin baseline SHA/digest and link note 18 §14 plus note 17. Every packet names itself characterization, implementation, or qualification; only qualification may produce promotion evidence.

## P0 — Establish one authority and scheduler before assigning work

**Risk.** Notes 23 and 24 intentionally own scenario rationale, not task definitions. Note 18 plus the manifest generated by `PLAN-001` are the only task/dependency authority, and the initial merge-ready set is only `PLAN-001`. Parallel agents using prose waves or addenda as permission can create duplicate owners, contradictory profile closure, and unmergeable cross-cutting edits.

**Foundation wording.** “Before implementation assignment, merge `PLAN-001` and select exactly one manifest profile (`lane` plus permitted `features`). The scheduler, not prose ordering, emits the ready set. A packet without a generated task ID, profile expression, principal write boundary, contract hash, owner, and integration runner is research only and cannot merge.”

**Route.** Scheduling/admission. Reject duplicate artifact ownership, prose alternatives, disabled capability work, and a required dependency marked N/A.

## P0 — Freeze the first-profile public trust boundary

**Risk.** Current direct `GET /v1/shape` accepts table/predicate inputs and the engine has control/visualization routes. The target first profile has one authenticated gateway only; public requests carry server-owned template/version and typed parameters, while engine, DS, PG, API, admin, metrics, and diagnostics stay private. A broad “secure endpoints” task could expose debug routes, leak DS identifiers, or make the compatibility adapter the authorization layer.

**Foundation wording.** “A direct engine or isolated adapter is non-promotion test plumbing. The only first-profile public data boundary is the authenticated proxy gateway. Clients never submit a table, predicate, projection, shape/subscription ID, DS path/URL, or admin operation; they cannot enable a disabled capability. Gateway denial occurs before registry, engine, DS, or PG work.”

**Route.** Boundary/non-goals and `SEC-000`, `PROTO-001A/B`, `SEC-004–006`, `E2E-002R/Q`. Keep direct Electric compatibility isolated until its gateway mapping is qualified.

## P0 — Preserve engine integrity invariants

**Risk.** Infrastructure work can violate engine guarantees while still showing eventual SQL equality.

**Foundation wording.** “Postgres remains the source of truth; derived arrangements are rebuildable and no hot-path table copy becomes authoritative. Snapshot/live joining uses xid visibility (`SnapshotGate`), not a bare LSN. Ingest is at-least-once and stateful consumers retain the sequencer's `(lsn, seq)` high-water. A source transaction is not visible or checkpointed past its terminal marker. An acknowledged shape batch is landed with reliable append or the shape is durably retired—never discarded. Drift/TRUNCATE/identity regression retires dependents; unproven slot, catalog, DS, or timeline continuity fails closed or performs one authorized whole-generation reset. Circuit structure never scales with subscriptions or parameter combinations.”

**Route.** Non-negotiable-invariants block, linking `AGENTS.md` and note 18 `ENG-002/004/007A/014/015/017`, `STO-*`, and `DSR-*`. Every engine/storage packet maps changed behavior to an invariant and test.

## P0 — Make PG18 topology an executable exclusion set

**Risk.** PG18 is the target baseline but not the current Compose default. Its observed virtual-generated-column snapshot/live divergence is a P0 blocker. A loose migration to “Postgres 18” can retain PG16 evidence, accept a half-schema, trust a recreated slot by name, or imply seamless promotion.

**Foundation wording.** “The launch topology is one writable PG18 primary, one explicit immutable publication, one `pgoutput` slot, one active engine, and one file-backed DS on a single-writer RWO volume. Verify SCRAM and `verify-full` TLS independently for setup/admin, pool/backfill/query-back, and walsender. Reject virtual generated columns, unpublished stored generated or identity fields, and tracked-table RLS; use one publishable-column schema in admission, snapshot, live decode, drift, reactivation, and restore. Any slot invalidation, unproven durable-frontier continuity, or timeline change fences freshness and requires fail-closed handling or authorized reset. Same-name synchronized failover slots do not make promotion seamless.”

**Route.** Topology/compatibility and `PG18-000` before shared PG changes; proof belongs in `PG18-001A/B/Q`, `PG18-002A/B/C`, `OPS-003A/B`, `PGR-001`, `OPS-004`, and `PG18-003Q`. Require a PG18 image digest and reject fallback to PG16.

## P0 — Require authentic red-first TDD provenance

**Risk.** “TDD” can be laundered by a test written after code, expected failure, environmental timeout, or weak oracle—especially with split test/implementation ownership.

**Foundation wording.** “For a behavior change, register/select the stable scenario and contract hash, record a red run from the exact candidate patch (command, image/config/profile, seed, expected public oracle, actual observation, first divergence), then make that unchanged contract green. With separate owners, use a stacked patch: implementation consumes the recorded red patch and integration merges only the green pair. Skipped, inverted, permanently expected-failure, changed-hash, or environment-only red evidence is not TDD and cannot close a gate. Mutation/disabled-hook checks must show the oracle catches the intended bad behavior.”

**Route.** Packet evidence template and merge protocol; tie to `E2E-000S/I`, `TST-007`, and red contracts `E2E-001R`, `002R`, `003CR`, `003NR`, `004R`.

## P0 — Keep E2E contracts black-box and causally fenced

**Risk.** SQL after later writes, a separate sentinel feed, raw LSN/offset equality, or private catalog/circuit assertions can falsely prove client correctness and make tests refactor-hostile.

**Foundation wording.** “Stable E2E tests assert public behavior only: a named PostgreSQL `SourceCommitID` committed in the mutation transaction; `server.drainedThrough` after direct and deferred work; and a principal/template/generation-specific client fold/cache receipt after the target read and actual transaction commit. Compare against an independently authored SQL/journal oracle frozen at that source prefix. A separate sentinel, row-map equality, offset/handle/LSN, or private state is not a target receipt. Internal fsync/catalog/scheduler cuts are same-SHA instrumented diagnostics, never release-image contracts. Event/response replay is the core promise; one observer batch is only for selected `NATIVE_TXN_ATOMIC` streams.”

**Route.** `E2E-000A/B/I` and the scenario registry. Use event gates plus diagnostic deadlines, never sleeps; isolate DB, slot, DS volume/namespace, gateway tenant, and cache per test.

## P0 — Make security and operational failures mandatory proof

**Risk.** A happy-path slice can establish an unauthenticated data plane before negative behavior has a contract. Failure modes must not degrade into stale serving or disclosure.

**Foundation wording.** “No surface is production-ready without named negative cuts: malformed/expired/revoked credentials; parameter/PK/feed/path/offset substitution; revocation during create/renew/read/body; public-route scanning; plaintext/CA/SAN/identity rotation on every hop; response-loss and registry crash reconciliation; DS/catalog/PG restore combinations; disk/WAL/queue/FD/connection boundaries; SIGKILL/SIGTERM/stale-writer handoff; schema/publication/RLS mutation; and both PG18 promotion cases. Outcomes are only exact continuation, safe replay, completed retirement, typed refetch/reset, or admission rejection—never silent stale continuation. Evidence and telemetry exclude seeded secrets, raw predicates, DS locators, and row values.”

**Route.** Failure matrix: `TST-004`, `TST-010–012`, `SRV-E2E-*`, `GW-E2E-*`, `PG18-E2E-*`, and `BND-E2E-*`. Keep separate client and management networks; a direct-engine adapter cannot satisfy a gateway gate.

## P1 — Separate lanes and establish real-app provenance

**Risk.** `COMPAT_V1` and `NATIVE_CORE` promise different things. The app uses a customized vendored ElectricSync subtree, so sibling package tests cannot qualify it. Optional native features can be implied accidentally by broad shape success.

**Foundation wording.** “Choose one lane and exact feature set. Compatibility is only inventory-admitted eager/simple/single-owner templates through the actual vendored provider seam and real GRDB cache; unsupported calls fail before network work. Native core is independent of ElectricSync, GRDB, app DB, tRPC, and DS SDK; materialization requires a separately selected app owner. Record app commit, vendored subtree hash, proven upstream/patch provenance, schema/semantic epoch, and all server/client image digests. A sibling test result is conformance evidence only.”

**Route.** Profile selection and `CMP-000–006`, `NATIVE-ADR-001`, `SWF-*`, and `APP-NATIVE-{CONSUMER,SINK}-001`. Put the 199/200/201/400/maximum compatibility checkpoint matrix before a second eligible template.

## P1 — Treat ownership and integration as safety controls

**Risk.** Parallel work can create shared-file races, let qualification repair behavior it judges, or merge partial cross-runtime changes without production-evidence ownership.

**Foundation wording.** “One agent owns one generated task ID and declared principal boundary; it may read shared code but not claim another packet's artifact. Design/ADR/schema merges precede consumers; implementation precedes adversarial qualification; qualification cannot alter its contract or implementation. Each packet records starting SHA, scope, decisions, changed artifacts, commands/results, remaining risks, machine-readable evidence, and reviewer result in `notes/execution/<task-id>.md`. Integration tasks require a cross-boundary reviewer. Rebase, rerun direct gates, and regenerate the DAG/profile report before merge.”

**Route.** Collaboration section, aligned with note 18 §13. Name integration packets as evidence aggregators, not implementation catch-alls.

## P1 — Make validation and completion non-launderable

**Risk.** The baseline is not all green: Vitest is deterministically 284/285 because purge acknowledges before stream retirement, and the external Electric suite is blocked because `mix` is missing. Green Rust/Swift tests do not reverse those facts.

**Foundation wording.** “A task outcome is `pass`, `fail`, `blocked`, or validator-produced `not_applicable_by_profile`; only pass and valid generated N/A promote. Skipped/filtered/zero-test/under-run/stale-or-wrong SHA, digest, config, profile, or contract hash fail. `blocked` is evidence, never completion. Local work reports exact AGENTS.md gates attempted; release evidence additionally requires selected-profile immutable-candidate tests, external Electric lanes, browser/live-path verification where applicable, and the finite fault/capacity corpus. The current purge mismatch and absent external toolchain remain explicit blockers.”

**Route.** Definition of done, evidence schema, and `TST-000/001/003`. Preserve AGENTS.md's typecheck, engine test, full Vitest, and external oracle reporting rather than a shortcut.

## P1 — Guard against unsafe broad edits and false scope completion

**Risk.** “Foundation” and “production readiness” can encourage rewrites across routing, clients, Compose, deployment, docs, and app code, or make dev defaults look production-like without the underlying contracts.

**Foundation wording.** “A task changes only its principal boundary and declares every interface/config migration. It may not broaden public reachability, enable an excluded feature, weaken an invariant/test, silently change default topology, use production secrets/endpoints, or delete/overwrite unrelated work. A cross-boundary need becomes a manifest edge and integration packet. Demo/direct-engine settings remain non-production. Completion means accepted contract and evidence, not a large compiling diff.”

**Route.** Scope/safety and code-review checklists. Require limit-1/limit/limit+1 and fail-closed tests for admission/config changes; reset, restore, and publication mutation remain operator-authorized rehearsal operations.

## P2 — Preserve finite, reproducible qualification

**Risk.** Calendar monitoring, mutable images, moving allowlists, or global-only counts make evidence irreproducible and hide missing templates/cuts.

**Foundation wording.** “Qualification uses checked-in fixed-operation manifests: seed; attempted/offered/admitted/committed/applied/compared counts; per-template floors; cut IDs; deadlines; resource caps; digest/config/profile/contract hashes; and signed pre-run divergence allowlist. Candidate artifacts are content-addressed and never rebuilt after testing. A smaller focused test has a named proof obligation; it does not replace the release corpus. Changed contract, allowlist, digest, or profile restarts the affected stage.”

**Route.** Capacity/evidence: `CAP-*`, `BND-E2E-*`, `E2E-005`, and `RLS-001`.

## Minimum admission checklist

Before high-parallel implementation, require evidence that:

- `PLAN-001` generated the selected profile's ready set and artifact ownership map.
- Current direct surfaces, PG16 development Compose, known purge failure, and missing external toolchain are recorded as current-state facts—not normalized away.
- `PG18-000`, `TST-000`, and the scenario/harness foundation are scheduled by the generated graph; no addendum self-authorizes an implementation packet.
- Every assigned packet has red/green provenance, an external oracle/cut tier, invariant mapping, completion evidence, and reviewer/integration destination.
- The gateway-only boundary, first-profile exclusions, safe topology, and operational negative tests are visible before rollout, migration, or public exposure work.

Without these, work may continue as bounded research or characterization, but must not be called implementation-qualified, production-ready, or ready for parallel merge waves.
