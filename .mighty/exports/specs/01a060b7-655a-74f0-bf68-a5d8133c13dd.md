Summary: A source’s status tells a consumer where its change log is and how far it has been written, and lists the consumers reading it.
## Interface
- `SourceStatus` (circuitsd `PUT/GET /admin/sources/{id}`) gains `change_log: { route: "/sources/{id}/changes", epoch: data_epoch_id, position: { segment, offset } }` and `consumers: [{ id, position, lag_segments }]`.
- Engine: `GET /changes/position` returns the log’s current `(segment, offset)` and open segment list; consumer listing comes from the pins spec.
## Guarantees
- The route in status is exactly the path the reader spec serves; a consumer built only from status can start reading.
- Position reflects the last acknowledged append, never an in-flight chunk.
- Adding these fields is backward compatible for existing clients: no field is removed or renamed.
## Verifications
- Activate a source -> status carries `change_log.route`, `epoch`, and a position that matches `GET /changes/position`.
- After a commit -> the status position advances; during a chunked commit it does not advance until the last chunk is acknowledged.
- Register a consumer -> it appears in `consumers` with `lag_segments` 0; rotate past it -> lag increases.
